## 一、项目用途与功能定位

这是一件**数字礼物**，而非常规业务系统。它把一组照片、几句心里话和一段程序化音乐，编排成一个约 1 分半钟的**沉浸式叙事体验**，最终目的只有一句话——**"甜甜，我喜欢你。"**

功能定位可以概括为三个关键词：

| 维度 | 定位 |
|------|------|
| **形态** | 单页、单文件、纯前端静态页（`site/index.html`） |
| **场景** | 手机竖屏为主，桌面同样适配，用于一对一的私密分享 |
| **体验** | 五幕式线性叙事 + 触摸/长按交互 + 星野粒子动画 + 程序化环境音 |

**五幕叙事线：**

1. **序幕** —— 黑暗中一粒微光脉动，逐字浮现"甜甜，有你真好"，引导"轻触这粒光"。
2. **唤醒** —— 星空点亮，文字"其实有太多话想和你说，只是不知道该从哪里说起。"
3. **回忆** —— 四段照片碎片（月亮、影子、比心、票根）依次点亮，每条配一句旁白，顶部光点进度条记录收集进度。
4. **靠近** —— 文字"我把这些日子，一颗一颗收好了。"，需**长按** 2.4 秒环形进度条才可推进。
5. **揭晓** —— 手写**信第一页**浮现 → 交叉淡入淡出**翻到第二页** → 信纸溶解、粒子爆散并**汇聚成字**"甜甜，我喜欢你。"，最后出现"再看一次"按钮。

整个体验**完全离线**，没有任何网络请求——这对私人照片来说是很克制的隐私设计。

## 二、技术栈与主要依赖

核心原则是 **zero-dependency（零依赖）**：成品页面不引入任何框架、库、字体文件或音频文件。

### 运行时（成品页面）
| 技术 | 用途 |
|------|------|
| 原生 HTML5 + CSS3 | 布局、场景过渡、逐字动画（`@keyframes chIn`）、响应式（`clamp()`） |
| 原生 JavaScript (ES5 风格) | 场景状态机、交互、主循环 |
| **Canvas 2D** ×2 | 星野层（`#stars`）+ 特效粒子层（`#fx`） |
| **Web Audio API** | 纯代码合成的环境垫音与风铃音（无音频文件） |
| CSS 渐变 / filter | 暗角、辉光、字粒模糊 |

### 构建与验证工具链（开发期，不进入成品）
| 技术 | 用途 | 依赖来源 |
|------|------|----------|
| **Python 3** | `build.py`：读取图片 → Base64 内联 → 替换模板占位符 | 仅标准库 `base64/glob/os/re/sys` |
| **Node.js + playwright-core** | `verify.js`：无头 Chromium 驱动交互、定时截图、断言运行时状态 | 需外部安装（项目内**无** `package.json` / `node_modules`） |
| 本机 Chromium | 由 playwright 指定绝对路径启动（`ms-playwright/chromium-1228`） | 本机已装 |

> 关键结论：**成品零依赖，工具链却依赖好几个"环境假设"**——这正是后文"潜在问题"的主要来源。

## 四、核心执行流程与数据流向

### 4.1 构建期：照片 → 单文件

```
img/*.jpg  ──(正则 _(\d+)_\d+\.jpg$ 提取序号)──▶  命中 WANT={167,169,150,152,159}
                                                        │
                                          Base64 编码，加 data:image/jpeg;base64, 前缀
                                                        ▼
template.html  ──(字符串替换 {{IMG_*}})──▶  site/index.html（自包含，747 KB）
```

`build.py` 内置两道**失败保护**：缺少任一图片时打印 `MISSING` 并以退出码 1 终止；模板中找不到对应占位符时同样中止。这是一条可靠的"缺料即失败"流水线。

> 体积账：6 张原图合计约 **694 KB**，Base64 会膨胀约 33% → 约 925 KB，成品文件实测 **976 KB**（含 HTML/CSS/JS 本体）。**图片占成品体积的 95% 左右。**

### 4.2 运行期：五幕状态机的驱动

```
页面加载
   │
   ├─ resize()  ─ 按 DPR 缩放双 Canvas、生成星野、布局光点
   ├─ scene1()  ─ 序幕：星野暗(stars=0)、微光浮现、逐字打点
   └─ requestAnimationFrame(loop)  ◀──────────────┐
                                                  │ 每帧
   ┌──────────────────────────────────────────────┘
   ├─ starA 缓动逼近 starTarget（控制星野整体亮度）
   ├─ drawStars(dt)  星点下坠闪烁 + 偶发流星
   ├─ drawFX(dt)     爆散粒子 + 文字粒子飞行
   └─ 长按计时：holding 时推进环形进度，达 2.4s → finishHold()

用户交互（事件委托 + 指针事件）
   click on document ──┬─ s1：命中微光范围 → 爆散+风铃 → fade → scene2
                       ├─ s2：fade → scene3
                       └─ s3：按 data-step 在 orb → card → closing 间推进
   pointerdown/up on #hold ── s4 长按判定
   click on #replay ── 重置粒子与场景，回到 scene1

每次转场经过 fade()：黑幕覆盖 → 切场景 → 撤幕（0.88s 遮罩 + 0.12s 缓冲）
```

### 4.3 数据流向一览

| 数据 | 来源 | 变化 | 去向 |
|------|------|------|------|
| 照片 | `img/*.jpg` | 编译期 Base64 内联 | `IMG{}.moon/shadow/heart/ticket/letter` |
| 旁白文案 | `FRAGS[]` 常量 | 按 `fragIdx` 取用 | 照片卡标题 `#cardCap` |
| 星野状态 | 随机生成 `stars[]` | 每帧更新位置/亮度 | `#stars` Canvas |
| 粒子状态 | 字形栅格化采样 `textTargets[]` | `fly → text → settle` 相位推进 | `#fx` Canvas |
| 交互状态 | `cur`（当前场景）、`s3.dataset.step` | 点击/长按驱动 | 决定下一个场景切换 |
| 音频状态 | Web Audio 节点图 | 首次点击初始化；`muted` 开关 | 环境垫音 + 风铃 |

### 4.4 两个值得单独说的核心算法

**① 文字粒子（`buildTextTargets`）——"像素级"排版**

1. 用离屏 Canvas 以目标字号绘制一行汉字；
2. 按采样步长（随字号自适应）遍历像素，取 `alpha>128` 的坐标作为**粒子目标点**；
   > ⚠️ 采样步长通常是**非整数**，像素索引必须取整（`Y|0`/`X|0`）后再查表——TypedArray 用小数索引会返回 `undefined`，导致采样点集为空、成字彻底失效。此处曾长期存在该 bug，详见文末「变更记录」。
3. 用实际墨迹包围盒**二次居中**，抵消全角标点造成的视觉偏移；
4. 点数超 5000 时**等距降采样**，控制性能；
5. 每个粒子从屏幕外随机位置出发，用缓动函数在 2.9s 内飞向目标，并叠加正弦抖动。

**② 程序化音频（`initAudio` / `note`）——无音频文件的配乐**

- 环境垫音：4 个失谐振荡器（A 小调 110/164.81/220/329.63 Hz）→ 低通滤波（截止频率被 0.045 Hz 的 LFO 缓慢调制）→ 总线；
- 空间感：卷积混响，脉冲响应由**随机噪声 + 幂次衰减**现场合成（3.6s）；
- 交互音：8 音阶序列 `SCALE` 循环取音，正弦 + 2.003 倍频三角波叠加，指数包络衰减；
- 首次任意点击才创建 `AudioContext`——**合规地绕开浏览器自动播放限制**。

## 六、值得注意的设计模式

| 模式 | 体现 | 价值 |
|------|------|------|
| **模板 + 资源内联构建** | `template.html` + `build.py` → 自包含 `index.html` | 交付物只有一个文件，可离线、可直接分享、无跨域/CORS 烦恼 |
| **有限状态机（FSM）** | 场景级 `cur` ∈ {s1..s5}；场景内 `#s3` 用 `data-step` ∈ {orb, card, closing} | 状态收敛在少数变量里，防止重复点击导致的乱序 |
| **分层渲染 / z-index 编排** | stars(z1) → fx(z2) → vignette(z3) → scene(z4) → card(z6) → fadeout(z8) → sound(z9) | 各层职责单一，转场用黑幕层解耦，避免场景间互相干扰 |
| **事件委托 + 元素级兜底** | `document` 上一处 `click` 处理 s1/s2/s3；`#orb1`、`#orb3`、`#sound` 各自监听并 `stopPropagation()` | 减少监听器数量，同时保证小目标也能点中 |
| **缓动与统一时钟** | 单一 `rAF` 主循环，`dt` 上限 0.05s 防跳帧；`lerp/ease/clamp` 工具集 | 所有动画共享时间基准，行为一致、可预测 |
| **程序化内容生成** | 星野、粒子、音乐全部由代码生成 | 成品零素材依赖，体积可控 |
| **测试探针（Test Seam）** | 关键状态挂在 `window`（`cur`/`P`/`starA`/`textTargets`/`textSize`）供 `verify.js` 读取 | 无需构建测试框架即可做 E2E 断言 |
| **响应式/无障碍降级** | `clamp()` 流式排版；竖屏双行/横屏单行分支；`prefers-reduced-motion` 关闭动画 | 一套代码适配手机与桌面，尊重系统偏好 |
| **DPR 感知渲染** | `DPR=min(devicePixelRatio,2)`，Canvas 物理像素缩放，上限 2 防性能崩塌 | 高清屏锐利、低端机不卡 |

## 七、潜在问题与优化建议

按影响程度排序，**前三条是真正值得动手的**。

### 🔴 高优先

**1. 硬编码绝对路径，项目不可移植**
`build.py` 的 `ROOT`、`verify.js` 的 `OUT / URL / EXE` 全部写死了 `C:\Users\JT\Desktop\LOVE` 与本机 Chromium 路径。换机器、换用户名、改目录即失效。
→ 建议改用 `os.path.dirname(__file__)` / `__dirname` 推导根目录；Chromium 路径交给 `playwright` 环境变量或配置项。

**2. 验证脚本的隐性依赖未声明**（部分缓解，仍建议正式化）
`verify.js` 直接 `require('playwright-core')`，但项目没有 `package.json`、没有 `node_modules`。目前已通过把 playwright-core 装到隔离工作区 + `NODE_PATH` 指路的方式跑通，但这条依赖仍未写进项目。
→ 建议补一个极简 `package.json`（`dependencies: {"playwright-core": "^1.63"}`）并记一条安装命令；或改用 `playwright` 的默认浏览器解析，去掉硬编码 exe。

**3. 成品体积偏大，移动端首屏成本高**
`site/index.html` = **976 KB**（加第二页后增加约 230 KB），其中约 **95% 是 6 张 Base64 图片**。Base64 比二进制膨胀约 33%，且无法利用 HTTP 缓存（单文件特性使然）。
→ 建议：构建时对图片做**有损压缩 + 转 WebP**（`Pillow` 的 `quality=80` / `method=6`），预计可降到 250–350 KB；或按显示上限（信纸宽 380px）预先缩放，避免为 768×1024 以上的原图全额付费。

### 🟡 中优先

**4. 时序魔数与 CSS 过渡强耦合**（终章已改善，其余场景仍存在）
终章已把节奏抽成 `LETTER_TURN` / `LETTER_END` / `REPLAY_AT` 三个常量，并新增 `letterStage` 状态锚点；但前四幕仍有大量硬编码延时（`880/120` 遮罩节奏、`2400/1400` 点击间隔、`260/1600` 场景内延时），与 CSS `transition` 时长必须手工对齐。
→ 建议把剩余时长一并抽成常量（或 CSS 变量 + `getComputedStyle` 读取），集中在一处并加注释。

**5. 图片序号映射脆弱**
`WANT` 依赖微信文件名里的递增序号（167/169/150/152/159），正则也写死微信命名规则。原图重新导出、改名或换批，构建立刻失败。
→ 建议支持**按文件名/显式清单**映射（如 `love.config.json`），或加 CLI 参数覆盖。

**6. 交互可达性不足**
除 `#replay` 是 `<button>` 外，微光、照片卡、长按环均为 `div/p`，**键盘无法操作**，屏幕阅读器也难感知；仅声音按钮有 `aria-label`。
→ 建议给关键节点加 `role="button"` / `tabindex="0"` 与 `keydown`(Enter/Space) 兜底，长按交互提供点击替代路径。

**7. 逐字动画的性能开销**
`typeLine` 为每个字符创建一个 `<span>` 并施加 `blur(4px)` 过渡。长句在低端机上可能触发掉帧（blur 是较贵的滤镜）。
→ 建议对超长文本降级为整行淡入，或限制同屏 animating 元素数量。

### 🟢 低优先 / 清理项

**8. 素材未精简** —— `img/` 里 39 张（4.7 MB）实际只用 5 张，其余 34 张长期占用仓库。可移入 `img_unused/` 或删除。

**9. 代码冗余** —— `#orb1` 同时被 `document` 委托与元素自身监听（靠 `stopPropagation` 避免重复），逻辑重复；`scene3()` 中 `var el = $('s3').querySelector('.line')` 取而未用。

**10. 全局命名空间污染** —— 为服务测试探针，大量变量挂在 `window`（`cur/P/starA/textTargets/textSize`）。可改为挂在一个命名空间对象下（如 `window.__APP__`），既保留可测性又更干净。

**11. 验证脚本自身的脆弱性**（终章已改善，前四幕仍存在）
终章已改为 `waitForFunction` 等待 `letterStage`，不再猜时长；但前四幕仍用固定 `wait()` 猜测动画节奏，并依赖具体 DOM id 与全局变量，属于"实现细节耦合型"测试。
→ 建议把前四幕也改成等待状态信号（`window.cur` 已是现成锚点），彻底去掉对固定时长的依赖。

**12. 缺基本页面元信息** —— 无 favicon、无 `og:` 分享卡片。作为要发给对方的链接，加一张 `og:image` 预览图（如月亮那帧）会显著提升"点开前的心动感"。
